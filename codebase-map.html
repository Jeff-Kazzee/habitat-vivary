Habitat Vivary / Source map

One project.
One container boundary.

The command wrapper calls Docker Compose. Compose starts a development container and a network proxy. Your project folder and agent login volumes supply the writable state.

Linux host or dedicated WSL2 distribution
  habitat.sh → compose.yaml
    ├─ dev container → selected project + agent state volumes
    └─ proxy container → permitted network destinations
          ↑
      internal network ← dev container
Configuration and runtime
  • habitat.sh: explicit check, build, start, shell, status, and stop commands.
  • compose.yaml: containers, mounts, networks, volumes, and resource limits.
  • .env.example: local project name and path configuration.
  • Dockerfile.dev: development tools and non-root user.
  • Dockerfile.proxy: Squid proxy image.
  • squid.conf: destination-domain allowlist.
Setup and operational limits
  • Windows setup: dedicated WSL2 environment.
  • wsl.conf: per-distribution isolation settings.
  • wslconfig.example: optional host-wide WSL resource limits.
  • Security and limits: writable data, credentials, network, and build boundaries.
  • Origin: the local setup and its upstream components.
Verification and maintenance
  • verify-source.py: daemon-free configuration checks.
  • test-cli.py: command dispatch against a mock Docker executable.
  • check-node-security.py: actual Node runtime policy at build and startup.
  • test-node-security.py: affected-version and guard regression checks.
  • Source security workflow: daemon-free source checks without image publication.
  • Node security verification: release evidence and remaining image-build checks.
  • Verification: source checks and first-build checks.
  • AGENTS.md: maintenance instructions.
  • Export task: scope and completion conditions.
